# Data Provenance to Workflow Provenance

This repository contains the Jupyter notebooks and datasets used to reproduce the results presented in the **paper**. 
The project demonstrates how data provenance can be extracted from SQL query workflows and subsequently transformed into workflow provenance.

## Repository Contents

### Jupyter Notebooks

- **`dataset.ipynb`**  
  Sets up the PostgreSQL database and prepares the datasets required for the provenance analysis.

- **`extract_data-provenance.ipynb`**  
  Demonstrates how data provenance can be computed for a sequence of SQL queries.
  Each SQL query is first translated into a set of (functional) tuple-generating dependencies (f-TGDs), providing a formal logical representation of the query semantics.
  This intermediate representation enables various logical and structural optimizations.
  The optimized f-TGDs are then translated back into nested SQL queries, which are used to compute the provenance of the resulting query outputs.

- **`dataprov2workflowprov.ipynb`**  
  Demonstrates how data provenance generated by the previous steps can be transformed into workflow provenance, connecting individual data-level provenance information to the overall workflow structure.

### Datasets

The repository contains **five datasets** (`df_control.csv`, `df_1_20.csv`, `df_1_7_9.csv`, `df_5_20.csv`, `df_1_5_7_9.csv) used to reproduce the experiments and results reported in the **paper**.

## Getting Started

1. Clone this repository.
2. Ensure that **Python**, **Jupyter Notebook**, and **PostgreSQL** are installed.
3. Open and run **`dataset.ipynb`** to set up the PostgreSQL database and load the required datasets.
4. Run **`extract_data-provenance.ipynb`** to compute data provenance for the SQL workflows.
5. Run **`dataprov2workflowprov.ipynb`** to transform the generated data provenance into workflow provenance.

The notebooks are intended to be executed in the order shown above.
