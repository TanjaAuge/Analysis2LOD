# Data Provenance to Workflow Provenance

This repository contains the source code of an infrastructure-based approach to extract data provenance from SQL query workflows and subsequently transform into workflow provenance.

**Note that this software is a research prototype and may contain bugs and errors, i.e., do not use this in production.**

## Usage

### Software Requirements

Installation of the python package is required, e.g. by installing via pip:

```bash
pip install git+https://github.com/TanjaAuge/Analysis2LOD.git
```

### Data Configuration
The `extract_data-provenance.ipynb` notebook defines and calls `get_connection()` in its database connection cell. The connection parameters are loaded from `database_config.py.

Keep `database_config.py` in the same directory as `extract_data-provenance.ipynb`. Before running the notebook, replace the `xxx` placeholders for `user` and `password` in `DATABASE_CONFIG` with your PostgreSQL credentials. Adjust `dbname`, `host`, or `port` there if your database uses different settings. Do not commit real credentials to the repository.

### Running

Run the notebooks in this order:
1. Configure `database_config.py`, then run `extract_data-provenance.ipynb` to compute data provenance for the SQL workflows.
2. Run `dataprov2workflowprov.ipynb` to transform the generated data provenance into workflow provenance. 

## Repository Contents

### Jupyter Notebooks

- **`extract_data-provenance.ipynb`**  
  Demonstrates how data provenance can be computed for a sequence of SQL queries.
  Each SQL query is first translated into a set of (functional) tuple-generating dependencies (f-TGDs), providing a formal logical representation of the query semantics.
  This intermediate representation enables various logical and structural optimizations.
  The optimized f-TGDs are then translated back into nested SQL queries, which are used to compute the provenance of the resulting query outputs.

- **`dataprov2workflowprov.ipynb`**  
  Demonstrates how data provenance generated by the previous steps can be transformed into workflow provenance, connecting individual data-level provenance information to the overall workflow structure.

### Database configuration
`database_config.py` stores the PostgreSQL connection parameters used by `extract_data-provenance.ipynb`.
